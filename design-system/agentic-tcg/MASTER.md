# Agentic TCG — 에이전트 거래와 카드 탐색

랜딩의 최신 구조는 [랜딩 설계](pages/landing.md)를 우선 적용합니다. 아래의 기존 피카츄 비교·이브이 중심 랜딩 구조는 이전 설계이며, 검색·상세·색상·타이포그래피 규칙은 유지합니다.

상태: 실행 Web에 적용. [Web README](../../apps/web/README.md)에 실행·SSR·검증 범위를 정리합니다. [이전 코랄 플레이룸](../../docs/design/archive/coral-playroom.html)은 보관용이며 현재 디자인 기준이 아닙니다.

## 적용한 스킬과 우선순위

사용자가 선택한 **큰 이미지와 개성 있는 비대칭 구성의 컬렉터 쇼케이스**가 기준입니다. 이번 재구성에는 `ui-ux-pro-max`의 `collectibles gallery discovery --design-system`, `related products --domain ux`, `information hierarchy --domain ux`를 조회하고 `frontend-design`의 실제 콘텐츠 중심 원칙을 적용했습니다. 연관 상품에 대한 직접적인 UX 검색 결과는 없어 명시적인 이름·세트 연결을 일반 설계 판단으로 적용합니다.

추천 결과 중 흰 여백과 이미지 중심 갤러리·정보 위계만 적용합니다. 상품 검색 사이드바에 대한 직접적인 UX 검색 결과는 없어 일반적인 반응형 그리드로 설계합니다. 스크롤 스토리·자동 움직임·녹색 배경·후기·성과 수치는 채택하지 않습니다. **사용자가 지정한 순백 배경이 우선**입니다.

## 제품 목적

사용자가 원하는 카드·예산·거래 조건을 정하고 AI 에이전트가 거래를 수행하는 TCG 플랫폼입니다. 첫 화면은 이 역할을 설명하고, 카드 탐색과 원본 참고 시세는 거래 기준을 정하는 과정으로 연결합니다. 아트워크는 서비스 정체성의 대체가 아닌 탐색 예시입니다. 코랄은 조작에만 제한적으로 사용합니다.

공유 데이터는 카드 410장(영어 171장·한국어 239장), 영어판 한국어 종명 연결 136장, 이미지 URL 166개, 영어판 참고 시세 1,145개입니다. 한국어판은 제공자의 원문 이름을 유지하며 이미지·가격 자료는 없습니다. 별도의 합성 카드 3종과 가격은 데모로 구분합니다. 영어판의 한국어 표시 이름을 한국어 인쇄 카드로 오인하게 만들지 않습니다.


## 확인한 불편과 대응

- 랜딩이 한 장의 상세처럼 보임: 카드 속성 소개를 줄이고 피카츄의 서로 다른 그림을 나란히 전시합니다.
- 비대칭이 크기 차이로 끝남: 같은 포켓몬의 세트·그림 차이가 배치의 이유가 됩니다.
- 다른 카드를 볼 이유가 약함: 이브이와 진화형을 주제로 묶고 이미지에서는 상세, 이름에서는 같은 이름 검색으로 연결합니다.
- 상세에서 탐색이 끝남: 같은 이름의 다른 카드와 이름 검색을 제공하고 기존 검색 복귀 주소를 보존합니다.
- 제품의 시세 확인 경험이 드러나지 않음: 피카츄 카드 옆에 원본 EUR/USD 참고 가격과 출처·판본 확인 링크를 둡니다.

## 페이지 구조

### 랜딩 `/`

```text
브랜드                                                   홈 / 카드 검색

카드 거래는           Base Set 피카츄        Jungle 피카츄
AI 에이전트에게       큰 실제 이미지         약간 작고 낮은 실제 이미지
서비스 소개           세트·번호·언어          세트·번호·언어
[거래할 카드 찾기]     원본 참고 시세          원본 참고 시세
카드 둘러보기         시세 자세히 보기        시세 자세히 보기

이브이와 진화형
이브이                샤미드                 쥬피썬더           부스터
이미지 → 상세         이름 → 같은 이름 검색

원본 참고 시세와 인쇄 언어 안내

브랜드                                                   데이터 안내 펼치기
```

첫 제목은 ‘카드 거래는 AI 에이전트에게’로, 원하는 카드·예산·조건은 사용자가 정하고 거래를 에이전트에게 맡기는 서비스임을 설명합니다. 피카츄는 카드 탐색의 예시이며 서비스의 주제로 강조하지 않습니다. 주요 버튼은 카드 검색, 보조 링크는 아래 카드 묶음으로 연결합니다. Agent 실행 기능은 해당 모듈 연결 후 제공합니다.

소개와 검색 진입은 왼쪽, 예시 카드는 오른쪽에 큰 270px/작은 230px 폭과 88px 수직 차이로 배치합니다. 모바일에서는 소개 뒤에 카드 두 장을 유지하고 수직 차이를 줄입니다.

문구는 영어식 대구나 끊어진 슬로건 대신 자연스러운 한국어 문장으로 씁니다. 소개·안내·빈 결과는 해요체, 버튼은 ‘더 보기’·‘찾기’처럼 행동을 짧게 표현합니다. 통화·가격 출처·판본의 의미는 유지합니다.

주제는 명시적으로 고른 피카츄와 이브이·샤미드·쥬피썬더·부스터입니다. 추천·인기 순위나 수집 연도를 추론하지 않습니다. 이름 부분 일치·중복 UUID는 제거하고 이미지가 있는 카드를 우선합니다. 랜딩의 가격 조회는 피카츄 최대 두 장에 한정합니다. 주제·가격 요청 일부 실패는 성공한 다른 카드나 검색 진입을 지우지 않으며 실패와 빈 자료를 구분합니다. 눈썹 타이틀·장식용 번호·화살표·반복 배지·자동 움직임을 넣지 않습니다.

### 카드 검색 `/cards`

왼쪽 200px 검색 영역과 오른쪽 3열 카드 갤러리로 나눕니다. 검색 영역에는 제목·실제 이름 검색·가격 안내만 두며 미구현 필터를 만들지 않습니다. 목록의 카드명·세트·가격은 실제 카드 이미지의 왼쪽 끝에 맞춥니다. 화면이 좁아지면 2열, 768px 미만에서는 검색이 목록 위로 이동합니다.

랜딩 이미지나 소개 문구를 반복하지 않습니다. 검색어는 `/cards?q=검색어`, 상세와 복귀 링크에 보존합니다. 기존 `/?q=검색어` 주소는 새 검색 주소로 리다이렉트합니다. 초기화·없는 카드·오류 화면의 목록 복귀도 `/cards`를 사용합니다. 작은 결과 수는 빈 컬러 패널을 만들지 않고 같은 갤러리 규칙으로 진열합니다.

현재 API는 q/limit와 nextCursor:null을 제공합니다. 조회된 최대 20종 안에서 이미지 있는 카드를 먼저 보여줍니다. 세트 필터·전체 개수·페이지 이동은 backend 계약 확장 후 연결합니다. 받은 일부 데이터만 필터링하고 전체 검색처럼 표시하지 않습니다.

### 카드 상세

```text
검색으로 돌아가기 / 세트
────────────────────────────────────────────────────
큰 카드 이미지       한국어명 / 원문명
                    대표 가격·원본 통화
                    제공자·변형·검증 상태·갱신 시각
                    인쇄 언어 / 번호 / 에디션 / 보존 상태
────────────────────────────────────────────────────
참고 시세 | 평가 근거 | 카드 정보       실제 섹션으로 이동
해외 참고 가격 목록과 각 출처
USDC 평가와 근거 [펼치기]
한국어 표기 안내 / 내부 식별 정보 [펼치기]
```

첫 화면에서 가격을 확인하고 아래에서 근거를 비교합니다. 가격이 없는 것을 실패와 혼동하지 않습니다. 추정 적정가가 있으면 USDC를, 그렇지 않고 참고 시세가 있으면 원본 EUR/USD를 대표값으로 표시하며 미검증·원본 참고용이라는 설명을 함께 둡니다. 가격 패널을 겹쳐 같은 금액을 반복하지 않습니다.

이미지·가격 요약 아래에 같은 원문 이름의 다른 카드를 최대 3장 연결합니다. 현재 카드·중복·부분 일치 이름은 제외합니다. 다른 이미지 카드가 있으면 그 카드들로 구성하고, 모두 이미지가 없으면 대체 화면을 제공합니다. 연관 검색 실패가 카드 본문을 오류로 바꾸지 않습니다. 상세→상세 이동에도 처음 검색어를 보존합니다.

## 색과 타이포그래피

| 역할 | 값 | 규칙 |
| --- | --- | --- |
| 페이지·헤더·이미지 영역·정보 면 | `#FFFFFF` | 전체 배경은 순백 |
| 본문·제목 | `#24212D` | 아트워크와 가격을 읽는 기준 |
| 보조 정보 | `#6B6574` | 세트·시간·설명 |
| 브랜드 코랄 | `#C94F57` | 작은 표식·구분 강조 |
| 주요 버튼 | `#B6404B` | 흰 글자 대비 5.49:1 |
| 링크 | `#8B303E` | 밑줄/명확한 조작 형태 병행 |
| 구분선 | `#E5E2E8` | 얇은 구역 구분, 입력 경계의 대체 아님 |
| 입력 경계 | `#897F97` | 입력과 흰 바탕 구분 |

페이지 전체를 밝은 회색·보라·분홍으로 채우지 않습니다. 성공·오류·데모의 작은 의미별 라벨에는 지정 상태 토큰을 사용할 수 있지만 색만으로 상태를 전달하지 않습니다. 정상 작동하는 버튼이 코랄이라는 이유로 오류 상태를 뜻하지 않습니다.

- 글꼴은 저장소의 Pretendard Variable v1.3.9, 폰트 CDN 없음.
- 랜딩 주제 제목 36~56px / 600, 모바일 34px. 검색 제목 26px / 600, 결과 제목 16px / 500, 카드명 16~19px / 550, 본문 16px, 설명 13~15px, 보조 메타데이터 12px.
- 제목은 폭을 제한하고 `text-wrap: balance`를 보조적으로 적용합니다. 특정 단어만 꾸미거나 강제 줄바꿈으로 화면별 문장을 맞추지 않습니다.
- 가격은 tabular-nums로 표시하고 원본 숫자의 정밀도·통화를 보존합니다. 반복 배지 대신 간결한 라벨과 상세 근거를 사용합니다.

## 반응형과 상태

- 최대 컨테이너 1280px, 데스크톱 좌우 32px, 모바일 20px. 헤더·본문·푸터의 기준선을 맞춥니다.
- 목록은 검색 영역 옆 3열 → 1100px 미만 2열이며, 768px 미만에서 검색 영역이 위로 이동합니다. 타일 최대 폭은 240px이고 이미지 비율에 맞춰 높이를 예약합니다.
- 랜딩은 소개와 두 이미지의 비대칭 구성, 768px 미만에서 소개가 위로 이동합니다. 이브이 묶음은 4열→2열입니다. 검색은 별도 페이지입니다.
- 상세는 768px 미만에서 한 열로 바꾸고 원본 가격 표도 모바일 행 묶음으로 읽을 수 있게 합니다.
- 클릭 영역 44px 이상, 키보드 포커스 유지. 그림 설명은 색·hover에만 의존하지 않습니다.
- 사용자 요청에 따라 카드 hover·포커스의 작은 이동과 패널 전환을 적용합니다. [모션 기준](pages/motion.md)을 우선 적용하며 자동 반복·스크롤 연출은 사용하지 않습니다.
- 이미지 실패는 이름·세트가 있는 대체 화면으로 복구합니다. hydration 전에 실패한 요청도 확인합니다.
- 가격 API 일부 실패는 목록을 지우지 않습니다. 자료 부족과 조회 실패는 서로 다른 문구를 사용합니다.
- 카드 이름·세트·가격 종류·통화는 목록에서 바로 확인하고 상세에서 원문·판본·상태·근거를 확인합니다.

## 분할 화면의 에이전트 대화

`ui-ux-pro-max`의 `conversational AI split workspace --design-system`, `chat keyboard input --domain ux`를 참고했습니다. AI 대화 영역이라는 분류와 최소한의 UI만 적용하며, 추천 보라 배경·타이핑 애니메이션은 사용하지 않습니다. 순백·코랄·Pretendard를 유지합니다.

```text
브랜드                  홈 / 카드 검색 / 에이전트 접기
카드 탐색 또는 상세       | 거래 에이전트
독립적인 본문 스크롤      | 대화 내용 스크롤
                         | 입력창 / 보내기
                         | Agent 연결 전 안내
```

- 900px 이상에서 왼쪽 가변 영역과 오른쪽 360px 영역을 나눕니다. 팝업·백드롭은 사용하지 않습니다.
- 좁은 화면은 카드 탐색과 대화를 탭으로 전환합니다. 두 영역은 DOM에 유지하며 CSS로 표시를 전환합니다.
- 공통 레이아웃에서 대화를 유지하므로 페이지 이동과 패널 접기가 입력 내용을 지우지 않습니다. 새로고침하면 초기화합니다.
- 대화는 로컬 UI 미리보기입니다. 허위 AI 응답·처리 중 애니메이션·주문 성공 상태를 만들지 않습니다. 입력창 아래에 미연결 안내를 둡니다.
- 대화 예시는 입력만 채웁니다. 공백 보내기 금지, 2,000자 제한, Enter/Shift+Enter와 한글 조합을 구분합니다.
- 실제 남은 본문 폭에 맞춰 container query로 랜딩·검색·상세를 재배치합니다.

## 정책·거래 관리 화면

`ui-ux-pro-max`의 `trading account dashboard --design-system`, `dashboard data tables --domain style`, `form error validation --domain ux`를 참고했습니다. 자동 제안된 다크 테마·기업 홍보 패턴은 적용하지 않고, 데이터 표와 정보 위계·포커스 가능한 오류 요약을 사용합니다. 순백 배경과 Pretendard, 기존 코랄 버튼을 유지합니다.

- 서비스 메뉴는 본문 상단에 고정합니다. 카드 검색·매물·내 카드·거래 관리·설정·로그로 이동하며 좁은 화면에서는 메뉴 안에서만 가로 스크롤합니다.
- 각 거래 화면은 예시 데이터 안내 → 제목·설명 → 요약/필터 → 표 또는 설정 폼 순서입니다. 장식용 눈썹 타이틀이나 가짜 실적을 넣지 않습니다.
- 표의 카드 이미지·이름과 금액을 같은 행에 정렬합니다. 실제 본문 폭이 760px 이하이면 필드명을 표시하는 세로 행으로 재배치합니다.
- 정책은 허용 카드·예산·1회 한도·할인율·유효 날짜를 설정합니다. 입력 오류는 해당 필드와 상단 요약에 함께 표시하고 오류 요약으로 포커스를 옮깁니다.
- 결제 확인·실패·진행 중·결과 미확인을 구분합니다. 미확인 상태에 재결제를 유도하지 않으며 실패 예시만 재시도 화면을 제공합니다.
- 거래 관련 상태와 금액은 모두 합성 예시입니다. 화면 간 상태는 공통 메모리 Provider에 유지하며 새로고침하면 초기화합니다. 주문·지갑 서명·결제·Agent 실행은 서버로 요청하지 않습니다.
- 상세 번호·로그를 펼쳐 볼 수 있고 상태·이름 필터로 빈 결과도 확인할 수 있습니다. 카드 검색과 대화의 분할 레이아웃은 유지합니다.

## Emotion과 데이터 경계

파일 상단에 import·타입, 그 다음 컴포넌트, **같은 파일 하단에 styled/css 선언**을 둡니다. 별도 styles 파일로 분리하지 않습니다. 팔레트는 `src/styles/theme.ts`에서 관리하고 스타일 전용 props는 DOM으로 넘기지 않습니다.

페이지와 API 조회는 Server Component 및 `server-only` 모듈에 유지합니다. 화면 컴포넌트는 DTO를 받아 표현하며 Core API URL이나 비밀값을 브라우저에서 읽지 않습니다. 요청별 Emotion cache와 `useServerInsertedHTML`로 전역/일반 규칙을 head에 주입합니다. 해당 앱·버전에서 SSR·클라이언트 이동·hydration을 검증하며 일반적인 라이브러리 전체 호환성을 보증하지 않습니다.

현재 카드 탐색·상세는 Core API와 연결되어 있습니다. 대화·Agent 설정·정책·예산·매물·내 카드·주문·결제·거래 내역·로그는 미리보기 상태이며 실제 API/SSE 연동은 후속입니다.
