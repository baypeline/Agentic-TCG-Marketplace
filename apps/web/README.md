# Next.js Web

순백 배경의 랜딩(`/`), 카드 검색(`/cards`), 카드 상세(`/cards/[id]`) 화면입니다. 랜딩은 거래 조건 설정과 에이전트의 구매 과정을 설명하며 카드 탐색을 보조 콘텐츠로 제공합니다. 검색은 좌측 검색과 우측 갤러리, 상세는 큰 이미지와 가격·근거를 담당합니다. 페이지는 Server Component로 유지하고 `server/api.ts`에서 `CORE_API_URL`의 Fastify를 호출한 뒤 공통 Zod Schema로 응답을 검증합니다. Emotion을 사용하는 표현 컴포넌트에 DTO를 전달하며 API 주소·환경변수를 브라우저 코드에서 읽지 않습니다.

[디자인 기준](../../design-system/agentic-tcg/MASTER.md)을 `@emotion/styled`로 구현했습니다. `ui-ux-pro-max`의 E-commerce·제목 균형·정보 위계·색 이외 상태 전달 가이드를 참고했습니다. 배경은 사용자 지정에 따라 `#FFFFFF`로 고정하고 코랄은 검색·링크 등 조작에 사용합니다. [이전 코랄 플레이룸 HTML](../../docs/design/archive/coral-playroom.html)은 비교용 보관본으로 현재 UI와 다릅니다.

## 에이전트 대화 UI

공통 `AppShell`의 에이전트 패널은 기본 닫힘입니다. 상단 ‘에이전트 열기/닫기’ 버튼을 모든 화면 크기에 제공하며 내부 닫기 버튼·Escape로도 닫을 수 있습니다. 명시적으로 열면 입력창으로, 닫으면 상단 열기 버튼으로 포커스를 이동합니다. 데스크톱에서 열면 왼쪽 본문과 오른쪽 360px 대화 영역으로 나뉘고, 모바일에서는 팝업 없이 본문 대신 대화 영역을 표시합니다. 별도 모바일 대화 탭은 없습니다. 각 영역은 독립적으로 스크롤하며 입력은 패널 하단에 유지합니다. 본문은 `browse` container query로 실제 남은 폭에 맞게 재배치합니다.

`stores/agent-panel.ts`의 Zustand `persist`는 localStorage의 `tcg-agent-panel`에 열림 여부만 저장합니다. `skipHydration`으로 서버와 첫 클라이언트 렌더를 닫힘으로 일치시키고 마운트 후 저장값을 복원합니다. 저장값에 임의 필드나 잘못된 값이 있어도 액션을 덮어쓰지 않습니다. 카드·예산·결제·대화 내용은 이 저장소에 넣지 않습니다.

랜딩에서는 서비스 탭 줄을 숨기고 상단 ‘마켓 둘러보기’(모바일 ‘마켓’)와 본문의 구매·판매 진입을 제공합니다. 카드 검색·매물·내 카드·거래 관리·에이전트 설정·로그 메뉴는 서비스 화면의 고정 탐색 영역에서만 표시합니다. 브랜드 링크는 모든 화면에서 홈으로 연결됩니다.

`features/chat/agent-chat.tsx`는 공통 레이아웃에 유지되므로 카드 검색·상세 이동과 패널 접기에도 메시지와 작성 내용이 보존됩니다. 새로고침하면 초기화되며 localStorage나 서버에는 저장하지 않습니다. 예시 문장은 입력창만 채웁니다. Enter는 보내기, Shift+Enter는 줄바꿈이며 한글 조합 중 Enter는 보내지 않습니다. 공백 전송은 막고 입력은 2,000자로 제한합니다.

검색 폼은 `next/form`의 GET 클라이언트 이동을 사용해 검색 제출 시에도 공통 레이아웃과 대화를 유지합니다. 문서 전체를 새로 불러오는 일반 HTML 검색 폼으로 되돌리면 대화가 초기화됩니다.

**현재 Agent 대화 API/SSE는 연결하지 않았습니다.** 입력한 메시지는 로컬 UI에서만 표시하고 실제 AI 답변·주문·결제를 만들지 않습니다. 미리보기와 미전송 상태를 화면에 명시합니다. 대화 API 연결 시 응답과 거래 상태를 이 UI에 연동합니다.

## Emotion 코드 배치와 SSR

파일 상단에 import·타입을 두고, 컴포넌트를 먼저 정의한 다음 **같은 파일 하단에 styled와 css 선언**을 둡니다. 별도 `Component.styles.ts`로 분리하지 않습니다. Theme 토큰은 `styles/theme.ts`, Theme 타입은 `styles/emotion.d.ts`에서 관리합니다. 스타일 전용 props는 DOM으로 전달하지 않습니다.

`app/providers.tsx`는 ThemeProvider와 `EmotionRegistry`를 조립합니다. Registry는 요청마다 cache를 생성하고 `useServerInsertedHTML`로 새 스타일을 head에 주입합니다. 전역 스타일과 일반 스타일을 분리하고 서버 요청 사이에 cache를 공유하지 않습니다. `GlobalStyles`는 reset·글꼴·포커스·reduced-motion을 관리합니다.

같은 공통 Providers의 `QueryClientProvider`가 전체 하위 트리에 TanStack Query를 제공합니다. `lib/query-client.ts`는 서버 렌더마다 새 QueryClient를 만들고 브라우저에서는 같은 인스턴스를 재사용해 요청 간 캐시 공유와 재렌더 시 캐시 초기화를 방지합니다. 캐시 영속화나 Devtools는 연결하지 않았고 기본 옵션을 유지합니다. 기존 Server Component의 카드 조회와 거래 화면의 로컬 미리보기는 그대로이며 실제 API 연동 시 `useQuery`·`useMutation`을 추가합니다.

모션은 `theme.motion`의 150/220/280ms와 공통 easing을 사용합니다. 패널은 그리드 폭과 opacity·translate를 전환하고 닫기 중에도 DOM을 유지하며 inert·aria-hidden으로 입력과 접근성 노출을 즉시 막습니다. 모바일은 같은 본문 영역 안에서 전환합니다. 연결된 카드 이미지에만 hover·키보드 포커스의 작은 상승·확대와 누름 피드백을 주고 상세 이미지·썸네일은 제외합니다. 버튼 색상과 새 대화 메시지에도 짧은 전환을 적용합니다. prefers-reduced-motion에서는 패널·메시지 모션과 카드 변형을 제거합니다. [모션 기준](../../design-system/agentic-tcg/pages/motion.md)에 상세 값을 정리했습니다.

Next.js 16.4.6 / React 19.3.1 / Emotion react 11.14.0·styled 11.14.1에서 개발 서버와 production 빌드의 직접 진입·목록→상세 클라이언트 이동·스타일 유지 및 hydration 오류 부재를 확인했습니다. 향후 라이브러리 업그레이드 시 다시 확인해야 합니다. 일반적인 App Router 전체 호환성을 보증하는 의미는 아닙니다.

## 탐색과 데이터 표시

실제 이미지 URL은 카드 비율을 유지해 표시하며, 누락·요청 실패 시 이름과 세트가 있는 대체 화면을 제공합니다. hydration 전에 실패한 이미지도 복구합니다. Pretendard Variable v1.3.9는 WOFF2와 OFL 고지를 저장소에 포함하고 `next/font/local`로 제공해 외부 폰트 CDN이 필요 없습니다.

현재 API에 맞춰 `/cards?q=검색어`로 이름 검색과 둘러보기를 제공합니다. 이전 `/?q=검색어` 주소는 새 검색 페이지로 리다이렉트합니다. 한 번에 최대 20종이며 조회된 범위에서 이미지가 있는 카드를 먼저 보여줍니다. 세트 필터·전체 결과 수·페이지 이동은 API 계약 확장 후 연결합니다.

랜딩의 첫 제목은 ‘카드 구매는 AI 에이전트에게’로 구매 위임과 직접 판매 등록의 역할을 구분합니다. 구매자는 `/agent`의 ‘구매 조건 정하기’, 판매자는 `/collection#owned-cards`의 ‘보유 카드 판매하기’로 진입하며 카드 검색은 보조 링크입니다. 오른쪽 설명용 예시의 네 버튼으로 조건 확인 → 매물 검토 → 결제 확인 → 카드 반영을 살펴봅니다. 예시 금액은 가상이며 실제 매물·평가·주문과 연결하지 않습니다. 단계 전환은 설명만 바꾸고 저장·서명·송금을 실행하지 않습니다. 실제 Agent 실행과 결제는 담당 모듈 연결 후 제공합니다. 안내는 해요체로 제공합니다. [최신 랜딩 설계](../../design-system/agentic-tcg/pages/landing.md)에 구조와 데이터 구분을 정리했습니다.

`server/discovery.ts`는 예시 카드인 피카츄·이브이·샤미드·쥬피썬더·부스터를 병렬 검색합니다. 원문 이름이 정확히 같은 카드를 이미지 우선으로 고르고 중복 UUID를 제외합니다. 피카츄 최대 두 장만 참고 가격을 추가 조회해 원본 통화로 표시합니다. 인기·추천 순위나 수집 연도는 추론하지 않습니다. 일부 조회가 실패하면 성공한 카드와 검색 진입은 유지하며 실패와 빈 자료를 구분합니다. Mock 모드에서는 공통 이미지 대체 화면을 사용합니다.

랜딩의 이미지는 상세, 이브이 묶음의 이름은 해당 이름 검색으로 연결합니다. 상세는 같은 원문 이름을 검색해 현재 카드와 부분 일치 이름·중복 UUID를 제외하고 최대 3장을 연결합니다. 이미지가 있는 다른 카드가 있으면 이를 사용합니다. 연관 조회 실패는 본문을 유지하며 처음 검색어는 상세 간 이동과 검색 복귀에 보존합니다.

목록은 카드별 평가·참고 가격 요청을 분리하고 동시 조회 카드를 4개로 제한합니다. 가격 조회 실패가 전체 검색 실패로 바뀌지 않습니다. 사용 가능한 평가가 있으면 데모/시장 USDC 가격을 구분하고, 그렇지 않으면 원본 EUR/USD 참고 가격과 제공자·변형·검증 상태를 표시합니다. 조회 실패와 실제 표본 부족도 구분합니다.

상세의 외부 참고 시세 영역은 `/api/cards/:id/prices`를 조회해 EUR/USD 원본 금액·가격 유형·제공자·관측 시각과 검증 상태를 표시합니다. 가격/판본/환율 근거가 있으면 링크로 제공합니다. 한국어판 실거래가와 구분하며 미검증 가격을 USDC로 표시하지 않습니다. 적정가 영역에는 사용 표본의 최근 관측 시각과 집계 표본 수의 의미를 표시합니다.

목록은 이름·세트·인쇄 언어·대표 가격으로 요약하고 상세 링크에 검증 상태를 보존합니다. 상세에서는 실제 이미지와 대표 가격·원본 통화·검증 상태·갱신 시각을 먼저 보여줍니다. USDC 평가·표본 수·신뢰 수준·평가 출처는 별도 펼침 영역에 둡니다. 없는 카드, 연결 오류 및 가격 표본 부족을 각각 구분하며 평가 요청만 실패해도 카드 속성은 유지합니다.

영어판은 한국어 표시 이름이 있으면 우선 표시하고 원문명을 함께 보여줍니다. 이 표기는 포켓몬 종명이며 한국어판 카드별 정식 제목과는 다를 수 있습니다. 한국어판(`KO`)은 TCGdex 한국어 카탈로그 원문 이름을 사용하며 상세 안내도 구분합니다. 인쇄 언어는 원본을 유지하고 표시 이름이 없으면 원문을 보여줍니다. 영어판 종명은 `pnpm cards:localize`로 연결하며 한국어판은 자동 종명 연결에서 제외합니다. `pnpm db:seed:collected`로 한국어 카드 239장을 포함한 카탈로그를 복원할 수 있습니다. 한국어판 이미지·국내 시세는 없으며 기존 대체 화면·자료 부족 상태를 사용합니다. Mock 데모도 기본 카드 3개의 한국어 검색을 지원합니다.

랜딩과 검색은 독립된 App Router 페이지입니다. 눈썹 타이틀·장식용 슬로건·반복 배지는 사용하지 않습니다. 카드 hover와 포커스는 아래 모션 기준을 따릅니다. 랜딩은 소개와 거래 예시의 2열이며 실제 본문 컨테이너 880px 이하에서 1열로 바뀝니다. 아래에는 예산·중지·처리 기록 안내와 실제 카드 최대 네 장을 배치하고, 650px 이하에서는 안내 1열·카드 2열로 전환합니다. 카드 조회 실패나 빈 결과여도 거래 설명과 설정 진입은 유지합니다. 검색은 200px 검색 영역과 3열 갤러리이며 1100px 미만 2열, 768px 미만 검색 영역 상단 배치로 바뀝니다. 카드 이미지와 이름·세트·가격의 왼쪽 끝을 맞추고, 타일 바깥 테두리와 색 매트 없이 아트워크를 직접 보여줍니다. 상세는 이미지/가격의 2열에서 모바일 1열로 전환합니다. 참고 시세 표는 모바일에서 행별 묶음으로 표시합니다. 입력 라벨·키보드 포커스·빈 결과·연결 오류·로딩 상태를 제공합니다.

## 거래 화면 미리보기

| 경로 | 화면 |
| --- | --- |
| `/agent` | 정책·허용 카드·총예산·1회 한도·유효 날짜, 실행·일시중지·중지 미리보기 |
| `/marketplace` | 고정가 매물 검색·상태 필터, 구매 주문 작성, 내 매물 취소 |
| `/collection` | 보유·판매·예약 상태와 거래 이력, 판매 등록 미리보기 |
| `/activity?view=orders` | 구매 주문 상태·상세, 일시중지·재개·취소 |
| `/activity?view=payments` | 결제 상태·상세, 실패 시 재시도 화면, 결과 미확인 안내 |
| `/activity?view=trades` | 구매·판매 거래 내역과 결제·보유 번호 |
| `/agent/logs` | 수준·내용 필터, 예시 이벤트와 상태 변경 로그 |

각 화면 상단의 ‘화면 미리보기’ 표시는 거래 기록과 금액이 합성 예시임을 알립니다. `features/trading/demo-cards.ts`만 수집 카드 메타데이터에서 발췌했으며 거래 가격은 실제 시세와 무관합니다. 새 화면은 Core API 없이도 렌더링되고 실제 카드 상세 링크만 기존 카탈로그로 연결합니다.

판매자는 내 카드에서 보유 중인 카드를 선택해 고정가 등록을 미리볼 수 있습니다. 랜딩·내 카드의 `SellerGuide`에서 판매 과정과 대금을 안내하고 등록 폼 제출 전에도 같은 대금 안내를 제공합니다. 판매 수익은 내부 모의 장부이며 판매자 지갑 지급·출금은 지원하지 않습니다. 거래 관리에서도 해당 행을 ‘판매 수익 기록 (모의)’로 표시합니다. 내 매물은 `/marketplace?owner=me`로 바로 열고 전체·내 매물·다른 판매자 필터를 제공합니다. 가격 변경은 취소 후 재등록, 예약 중에는 변경 없이 확인 대기, 이전 완료에는 거래 내역 확인으로 안내합니다. 실제 매칭·결제·소유권 이전 로직은 추가하지 않았습니다.

`DemoTradingProvider`가 브라우저 메모리에 예시 상태를 보관합니다. Next.js 클라이언트 이동 중에는 저장한 정책·주문·매물·결제 상태를 유지하며 새로고침하면 초기화됩니다. 카드의 판매 등록과 취소는 예시 보유 목록과 매물 목록을 함께 갱신합니다. 결제 재시도는 실패 예시를 진행 중으로만 바꾸며 결과 미확인 예시에 재시도 버튼을 제공하지 않습니다. 실제 Agent 실행·매칭·지갑 서명·결제·소유권 이전은 없습니다.

USDC 입력은 정수 최소 단위 문자열로 변환하며 소수점 6자리까지 처리합니다. 예산 표시는 예시 지출의 결제 확인·예약 상태를 합산하고 입금을 제외합니다. 이는 표시용 데모 계산이며 서버의 지출 정책·예약·결제 처리 규칙이 아닙니다. 정책 입력 오류는 필드와 포커스 가능한 오류 요약에 표시합니다. 기존 Contracts의 `SpendingPolicy`, `BuyOrder`, `Listing`, `InventoryItem`, `Trade`를 참조하고 공통 계약은 수정하지 않았습니다. 결제·로그의 UI 전용 모델은 실제 API 계약 확정 후 어댑터로 교체해야 합니다.

`/agent`·`/activity`의 서버 상태 패널은 GET `/api/trading-status` BFF로 실제 정책 예산·실행·구매 상태·완료 Trade 수익을 읽습니다. 5초 조회와 서버 remainingMs 기반 카운트다운을 제공하며 브라우저 절대 시각으로 예약 유효성을 판정하지 않습니다. UNKNOWN 재결제·FINALIZING 추가 지급을 제공하지 않습니다. 기존 쓰기 폼과 채팅은 미리보기이며 서버 정책·주문·결제를 변경하지 않습니다.

BFF는 HttpOnly `tcg_session` 쿠키 또는 Bearer를 전달합니다. 로컬 개발은 `WEB_DEMO_ROLE=buyer|seller`와 서버 데모 토큰 설정으로 읽기 상태를 확인할 수 있습니다. 토큰을 브라우저에 반환하지 않으며 production에서 데모 역할을 사용하지 않습니다. 조회 패널 해제·창 닫기는 서버 실행 중단 요청을 보내지 않습니다. 개발·시작 명령은 루트 `.env`를 로드하고 `PORT`를 사용합니다. 미설정 시 Next.js 기본 포트인 3000을 사용하며 실제 카드 검색에는 Core API가 필요합니다.

루트에서 `pnpm --filter @tcg/web test`와 `pnpm --filter @tcg/web typecheck`로 검증합니다.

단위 테스트는 가격 출처·통화·자료 부족·부분 API 실패·검색어 보존을 검증합니다. 실제 브라우저에서 360/390/768/1440px의 목록·상세, 이미지 요청 차단 시 대체 화면, 빠른 검색·빈 결과, 키보드 포커스와 reduced-motion을 확인했습니다. 재현 시 `pnpm build` 후 별도 포트의 `next start`에서도 SSR과 클라이언트 이동을 확인하세요.

거래 미리보기 테스트는 공통 DTO 일치, USDC 정밀도, 정책 입력 오류, 예산 표시, 매물·보유 상태 동기화를 검증합니다. production 브라우저에서는 설정 저장·오류 포커스, 매물 등록/취소→보유 목록, 주문 작성→거래 관리, 결제 실패/미확인, 로그 검색과 360~1440px 배치를 확인합니다. 이 시나리오에서 거래를 변경하는 네트워크 요청이 없어야 합니다.
