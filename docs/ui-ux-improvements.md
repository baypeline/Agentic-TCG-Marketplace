# 거래 UI/UX 개선

데스크톱과 Chrome 개발자도구의 375×667·390×844·430×932 화면에서 확인한 문제를 기준으로 개선했습니다.

- 모바일 헤더는 계정·탐색 영역을 두 줄로 배치하고 작업 영역 높이도 맞춥니다. 주요 메뉴 네 개와 더보기를 제공하며 더보기는 외부 클릭·Escape로 닫힙니다.
- `/agent`는 채팅 구매와 같은 정책의 남은 예산·건당 한도·총예산을 기본 표시합니다. 두 금액을 바로 수정하고 저장할 수 있습니다. 지출·예약·허용 카드·활성 여부·유효기간은 유지합니다.
- 최초 조회 시 정책이 없으면 구매와 동일한 기본 정책을 초기화합니다. Core `GET /api/agent/budget`, Web `GET /api/agent-budget`는 지갑 인증과 공통 DTO를 사용하며 다른 사용자의 정책을 선택할 수 없습니다.
- 지갑 생성·충전 상태를 확인하고 주소를 펼쳐서 볼 수 있습니다. 주소가 새로 발급되면 같은 사용자라도 첫 안내를 다시 보여줍니다. 브라우저에는 방문 계정과 공개 지갑 주소만 보존합니다.
- 구매 후보에는 실제 남은 예산·건당 한도·지갑 잔액을 표시하고 한도 초과·예산 부족·충전 필요를 구분합니다. 이미 제출한 결제는 예산 상태와 별개로 기존 상태를 확인할 수 있습니다.
- 비로그인 화면에는 로그인 안내를 표시합니다. 상세 거래 조건과 수동 주문 관리, 허용 카드 목록은 접어두어 기본 저장 경로를 짧게 유지합니다.
- 랜딩은 실제 카드 이미지를 먼저 보여주고 현재 결제 통화에 맞게 거래 안내를 표시합니다. 별도 화면 미리보기의 예시 상태와 실제 거래 안내는 구분합니다.
- 작은 높이의 채팅은 소개·입력창을 줄이고 요청 예시를 가로 목록으로 표시합니다. reduced-motion, 키보드 포커스, 입력 라벨은 유지합니다.
- 로그인 결과가 캐시에 먼저 도착해도 서버 HTML과 첫 브라우저 렌더가 일치하도록 공통 세션 훅에서 hydration을 처리합니다. 모바일 채팅의 내부 링크는 패널을 닫고 목적 화면을 보여줍니다.

검증은 계정별 예산 조회, 실제 값 표시, 지갑 주소 변경 안내, 구매 한도와 기존 결제 조회에 대한 회귀 테스트 및 타입 검사·프로덕션 빌드를 포함합니다. UI 점검 중 실제 결제·판매 등록·송금은 실행하지 않습니다. 휴대폰의 가상 키보드와 외부 지갑 앱 전환은 별도 실기기 확인이 필요합니다.
