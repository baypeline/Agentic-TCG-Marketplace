# 사용자별 에이전트 지갑

첫 지갑 로그인에서 서비스가 사용자별 EVM 지갑을 자동 발급합니다. 재로그인·동시 로그인·서버 재시작 시 같은 주소를 유지합니다. 기존 구매자의 충전된 서버 지갑은 그대로 가져오며 다른 사용자에게 공유하지 않습니다.

첫 로그인 후 `/agent`로 이동합니다. 에이전트 설정에서 전체 주소를 복사해 Maroo Testnet의 tOKRW를 충전하고 잔액을 새로고침할 수 있습니다. `/agent/wallet`에서도 확인할 수 있습니다. 잔액 조회 실패는 0 대신 확인 불가로 표시합니다. 충전은 예산을 변경하지 않으며 예산 설정은 별도로 저장합니다. 마루에서는 같은 지갑이 결제 금액과 가스비를 부담합니다.

## 설치와 보관

1. `pnpm db:generate`, `pnpm db:migrate`로 지갑 테이블을 준비합니다.
2. 기존 환경은 `pnpm agent:wallet:key:init`을 실행합니다. 새 `.env`는 `pnpm env:init`이 암호화 키도 생성합니다.
3. Core API를 재시작합니다. 기존 로그인 계정도 지갑이 없으면 발급합니다.

`AGENT_WALLET_ENCRYPTION_KEY`는 32바이트 hex 키입니다. 기존 값을 임의로 교체하지 마세요. DB와 키를 함께 복구할 수 있도록 별도 보관해야 합니다. 키를 잃으면 DB의 암호문만으로 지갑을 복구할 수 없습니다. 기존 키가 있으면 초기화 명령은 덮어쓰지 않습니다.

`auth.ManagedAgentWallet`은 주소와 AES-256-GCM 암호문·IV·인증 태그·키 버전을 보관합니다. 사용자·Agent·주소를 AAD에 묶고 복호화 후 실제 주소도 검사합니다. 개인키는 서명할 때 서버에서만 사용합니다. 브라우저·LLM·MCP에는 개인키나 암호문을 제공하지 않습니다. 키 내보내기·재발급 API는 제공하지 않습니다.

## API와 결제

- Core `GET /api/agent/wallet`, Web `GET /api/agent-wallet`: 로그인한 사용자의 공개 주소·체인·통화·잔액·생성 시각만 반환합니다.
- 로그인 응답의 `agentWalletAddress`는 서버가 확정한 전용 지갑 주소입니다.
- x402 구매는 인증된 사용자·Agent에 연결된 지갑으로 서명합니다. NFT 매물의 수신자도 같은 지갑입니다.
- 기존 건별 구매 승인·정책·예산·예약·만료 검증은 유지합니다. 자동 발급 자체로 송금하지 않습니다.
- 자체 퍼실리테이터는 Core의 인증된 등록 조회 API로 자동 발급 지갑을 확인합니다. 새 지갑마다 고정 허용 목록을 편집할 필요가 없으며 연결 해제도 다음 검증에 반영합니다. 기존 환경은 `pnpm facilitator:init`, `pnpm facilitator:up`으로 등록 조회 URL과 컨테이너를 갱신합니다.

실제 DB 테스트로 동시 발급·재로그인·기존 지갑 보존·잘못된 암호화 키·다른 Agent 접근 거부를 검증합니다. 사용자별 x402 서명과 NFT 수신자, 공개 응답의 비밀값 제외도 검사합니다. 로컬 HTTP에서는 두 신규 계정의 로그인·예산 분리·MCP 구매 준비·취소·로그아웃을 확인했습니다. 새 지갑은 잔액 0에서 시작하므로 실제 온체인 구매는 충전 후 가능합니다.
