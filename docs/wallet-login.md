# 지갑 로그인

상단 **지갑 로그인**에서 MetaMask 등 EIP-1193 브라우저 지갑을 연결하고 로그인 메시지에 서명합니다. 메시지 서명은 거래·송금을 승인하지 않습니다. 현재 프로필의 체인(마루 450815, Base Sepolia 84532)으로 전환한 뒤 서명합니다. 구현은 [Viem SIWE](https://viem.sh/docs/siwe/utilities/createSiweMessage)와 EOA 메시지 서명 검증을 사용합니다. WalletConnect와 스마트 컨트랙트 지갑의 ERC-1271 인증은 이번 범위에 포함하지 않습니다.

## 첫 로그인 안내와 지갑 설정

로그인 시 전용 에이전트 지갑을 자동 발급하며 첫 로그인 후 `/agent`의 충전 안내로 이동합니다. 안내를 본 계정 ID만 Zustand persist로 브라우저에 기억하며 다른 계정의 안내를 생략하지 않습니다. 브라우저 저장소를 비우거나 다른 기기에서 로그인하면 다시 안내할 수 있습니다. 안내를 이미 확인한 계정은 다시 자동 이동하지 않습니다.

`/agent`와 `/agent/wallet`에서 생성된 전체 주소·네트워크·잔액을 확인하고 주소를 복사해 충전합니다. 예산은 별도로 설정합니다.

개인키는 서버가 생성해 암호화하여 DB에 저장합니다. 재로그인해도 같은 주소를 사용합니다. [자동 발급·충전·암호화 키 보관](managed-agent-wallet.md)을 참고하세요.

## 설정과 복원

```powershell
pnpm db:generate
pnpm db:migrate
pnpm dev
```

`DATABASE_ENABLED=true`가 필요합니다. `AUTH_WEB_ORIGIN`을 생략하면 루트 `PORT`로 만든 `http://127.0.0.1:PORT`를 사용합니다. 로컬 개발에서는 같은 프로토콜·포트의 localhost도 허용하며 서명 메시지는 실제 접속한 주소로 만듭니다. 도전값을 발급받은 주소와 검증 주소는 같아야 합니다. `AUTH_WEB_ORIGIN`을 명시하거나 production이면 해당 주소만 허용합니다. 도메인·HTTPS 주소를 사용할 때는 Origin을 정확히 설정하세요. 경로나 마지막 `/`는 넣지 않습니다. HTTPS에서는 인증 쿠키의 Secure 속성도 설정합니다.

## 사용자와 자금

- `auth.WalletIdentity`는 소문자 지갑 주소를 고유 사용자 UUID·Agent UUID에 연결합니다. 재로그인과 서버 재시작 후에도 동일한 ID를 사용합니다.
- 기존 구매자 지갑인 `.env`의 `AGENT_WALLET_ADDRESS`를 서명으로 증명한 계정만 기존 데모 구매자·Agent UUID로 연결합니다. 기존 카드·소비·예약·거래는 옮기거나 초기화하지 않습니다. 서버 시작 시 이 주소를 보존한 뒤 실제 결제용 `AGENT_SERVER_WALLET_ADDRESS`를 별도로 사용합니다.
- 새 지갑은 빈 개인 계정으로 시작합니다. 개인 예산·거래 조회·보유 카드와 기존 데모 계정은 분리됩니다. 채팅의 예산 변경은 해당 사용자 정책에 저장됩니다.
- 로그인 시 사용자별 전용 지갑을 자동 발급합니다. 결제 서명과 NFT 수신자는 해당 사용자 지갑을 사용합니다. 기존 서버 지갑은 기존 구매자에게만 연결하며 운영자·판매자 역할은 유지합니다.
- 웹의 `WEB_DEMO_ROLE` 자동 로그인은 사용하지 않습니다. 익명 카드 검색은 가능하지만 거래·예산 설정에는 지갑 로그인이 필요합니다.

## 인증 경계

1. `POST /api/auth/challenge`: 주소를 받아 5분 SIWE 메시지를 만듭니다. nonce·웹 도메인·Origin·체인·시각·주소를 서버가 지정하고 브라우저 바인딩 값의 해시와 함께 DB에 저장합니다.
2. `POST /api/auth/verify`: 브라우저의 HttpOnly 도전 쿠키와 서명을 검증합니다. 클라이언트가 메시지·사용자 ID·Agent ID를 지정할 수 없습니다. 원본 메시지 서명과 현재 도메인·체인·브라우저 바인딩을 확인한 뒤 DB 트랜잭션으로 한 번만 소비합니다.
3. 8시간의 임의 세션 토큰은 SHA-256 해시로 DB에 보관합니다. 원문 토큰은 웹 서버가 HttpOnly·SameSite=Strict 쿠키에 넣고 JSON 응답에서 제거합니다. 쿠키는 JavaScript·localStorage·LLM에 제공하지 않습니다.
4. `GET /api/auth/session`은 만료·폐기를 확인한 로그인 상태를 반환합니다. `POST /api/auth/logout`은 서버 세션을 폐기하고 쿠키를 삭제합니다. 쓰기 요청은 동일 출처를 검사합니다.

위 경로는 Web BFF와 Core API가 동일한 경로를 사용합니다. 로그인·로그아웃·지갑 계정 변경 시 React Query 캐시와 사용자별 페이지·대화를 초기화합니다. 거래 응답 유실용 저장소는 사용자·Agent ID로 구분됩니다. 채팅 구매의 MCP 호출에도 인증된 동일 계정의 토큰을 전달하며 고정 데모 구매자 토큰으로 바꾸지 않습니다.

테스트는 실제 임시 EOA 서명의 검증, 잘못된 서명·출처·바인딩·nonce 재사용·동시 검증·만료 거부, DB 세션의 재시작 유지·로그아웃 폐기, 사용자별 예산·소유권 분리와 다른 사용자 지갑 접근 차단을 확인합니다. 실제 사용자의 브라우저 확장 지갑 팝업은 별도 수동 확인 대상입니다. 테스트 계정은 임시로 생성하며 실제 자금을 전송하지 않습니다.
