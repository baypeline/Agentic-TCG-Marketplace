# 채팅 예산 설정

현재 통화가 tOKRW이고 같은 요청에 `tOKRW`가 명시되어 있으면 `tORKW`를 전치 오타로 처리합니다. 예를 들어 “총 예산 100tOKRW, 건당 예산 20tORKW”는 총 100·건당 20 tOKRW의 확인 전 변경안을 만듭니다. 보정 사실을 답변에 표시하며 저장은 기존 확인 버튼으로 진행합니다. 통화 문맥이 없거나 KRW·USD 등 다른 통화이면 임의 보정하지 않습니다.

예: “총예산을 120 tOKRW, 건당 한도를 10 tOKRW로 설정해줘.” 또는 “총예산만 150 tOKRW로 바꿔줘.” 통화를 생략하면 현재 결제 통화를 사용합니다. USD·KRW를 자동 환산하지 않습니다. 총예산을 건당 한도로 해석하거나 지갑 잔액·입금액으로 예산을 초기화하지 않습니다.

1. Agent가 요청을 `update_budget`으로 분류하고 명시한 금액만 구조화합니다.
2. API는 채팅 구매가 사용하는 기본 정책을 읽어 변경안을 만듭니다. 정책이 없는 최초 실행은 기존 시연 기본 정책으로 초기화하며, 요청한 예산은 아직 저장하지 않습니다.
3. 웹은 현재·변경 후 총예산과 건당 한도, 소비·예약·사용 가능액을 표시합니다.
4. “확인하고 저장”을 눌러야 PolicyService의 버전 검사와 트랜잭션을 거쳐 DB에 저장합니다. 취소는 예산을 변경하지 않습니다. 같은 확인을 재요청해도 중복 적용하지 않습니다.

변경안은 5분 동안 유효하며 해당 대화의 최신 변경안만 사용할 수 있습니다. 새 메시지·대화 초기화·API 재시작 뒤에는 다시 요청해야 합니다. 소유자가 아닌 다른 대화에서는 변경안을 사용할 수 없습니다. 저장 시 다른 화면에서 정책을 수정했다면 새 변경안을 요청해야 합니다. 그동안 결제가 발생했다면 최신 지출·예약을 다시 확인합니다.

총예산은 이미 소비한 금액과 예약 금액의 합계보다 작을 수 없습니다. 건당 한도는 총예산과 서버 서명 상한(마루 25 tOKRW, Base Sepolia 0.025 USDC)을 넘을 수 없습니다. 사용 완료·예약액·허용 카드·활성 상태·유효기간은 유지합니다. 총예산을 건당 한도보다 낮추려면 새 건당 한도도 함께 요청해야 합니다.

예산 설정에는 지갑 로그인이 필요하며 로그인한 사용자·Agent의 기본 정책을 사용합니다. 다른 지갑이나 공통 데모 계정의 정책을 수정하지 않습니다. 기존 구매자 지갑으로 로그인하면 기존 정책·소비 기록을 이어서 사용합니다. 설정 화면에서 만든 별도 정책으로 자동 전환하지 않습니다. [지갑 로그인과 권한 범위](wallet-login.md)를 참고하세요.

Web BFF: `POST /api/agent/chat/budget`에 `sessionId`, `proposalId`, `action`을 전달합니다. Core API: `POST /api/agent/sessions/:sessionId/budget`. 금액은 브라우저에서 다시 받지 않고 서버에 보존한 변경안에서만 가져옵니다. `APPLIED` 응답의 `budget`은 저장 후 실제 원장입니다. 저장 응답이 유실되면 같은 확인을 재요청하거나 설정 화면에서 현재 정책을 확인합니다. 이 기능은 예산 설정만 변경하며 거래·서명·송금을 시작하지 않습니다.
